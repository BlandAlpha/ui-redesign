# 职业智能交互重设计记录

状态为待实施。本文记录能力证据、能力地图、职业记忆的走查和设计方案，供后续立项时使用。

## 走查发现

使用本地演示库，在 Chrome 的 `1440 px` 和 `390 px` 视口检查了三个页签。

| 区域 | 当前表现 | 影响 |
| --- | --- | --- |
| 能力证据 | 页内常驻长表单，窄屏首条证据约在页面 `1163 px`。点击「查看 / 编辑」直接进入复核表单。页签来回切换会保留草稿，打开另一条记录再取消会清掉新增草稿。 | 浏览、录入和复核共享一个入口，容易遇到滚动负担和输入丢失。 |
| 能力地图 | 手填逗号分隔的技能。输入 Python、Kubernetes、RAG 后显示 `67%` 和 `33%`，改填 React 后仍显示上一组结果，直到再次提交。点击证据会跳到编辑表单。 | 数字口径难扫读，结果与编辑中的条件容易混淆。待复核材料没有在对照结果中提示。 |
| 职业记忆 | 进入页签先看到七项录入控件。已确认、待确认和已过期记录混排。确认文案同时谈及准确性和继续使用。 | 难以快速回看求职条件，也难判断哪些记录当前可以用于 AI。 |

## 能力证据

- 默认展示列表和「添加证据」入口。可搜索标题、技能和贡献，优先提供「待复核」筛选。每行展示标题、个人贡献摘要、技能标签和复核状态。
- 点击记录先打开可读详情。来源定位、原文摘录、确认状态和 AI 使用权限在这里查看。桌面用侧边详情，窄屏用全屏详情。关闭后恢复列表的滚动位置、筛选和原入口焦点。
- 在详情中分别提供「编辑」「确认材料」「排除材料」。材料不完整时允许保留本机草稿。符合现有保存校验的记录支持「保存待复核」，核对来源、摘录、个人贡献与技能后可「确认并保存」。未来如需将不完整材料存成正式的待复核记录，应同步定义保存规则及迁移，保持确认和匹配的边界。
- 按新增任务或具体记录保存草稿。离开时能恢复；主动丢弃时说明后果。遇到版本冲突时保留已填内容，展示「查看最新版本」。改动或删除会重开关联成长任务时，在确认操作处提示影响。

## 能力地图

- 默认视图为「我的技能」。从用户确认或录入的材料标签建立清单，支持搜索和按技能打开关联材料。待复核材料在清单中保留状态。
- 「岗位对照」支持从求职资料库选择已有岗位，也支持手动添加技能。用可增删的标签确认范围，结果区显示岗位和已应用技能。条件改动后明确提示「有未应用的修改」。
- 结果用三个数量说明证据分布，分别是「有已确认的作品或面试材料」「仅有已确认的自述」「缺少已确认的材料」。已有待复核材料时另行标出。标签匹配反映材料覆盖情况，文案避免暗示熟练度或岗位录用判断。
- 为每种状态给出下一步。已确认材料可直接查看，待复核材料优先进入复核，缺少材料可以补充证据或加入成长计划。补充流程预填技能，返回时恢复原岗位、技能、筛选和位置，并用最新记录更新对照。
- AI 复盘放在结果旁作为次级操作。送出前用可读列表说明本次将使用的材料。由发送侧按确认、有效期、许可及本次选材结果确定清单，本地标签对照在无需配置模型时也可使用。

## 职业记忆

- 默认按分类浏览，优先展示求职目标、工作偏好和现实约束。支持查看待确认和已过期的条目，过期记录提供「更新有效期」入口。
- 添加时先填主题、分类、内容。手动录入来源默认「本人填写」，可展开补充来源和有效期。遇到同名主题时，允许从表单打开原记录，同时保留用户键入的内容。
- 分别展示本人确认、有效期和 AI 许可，许可默认关闭。详情直接显示当前实际状态，如「仅本机保存」「待确认，当前不会用于 AI」「已允许用于 AI」「已过期，当前不会使用」，并提供查看和撤回许可的入口。

## 建议实施顺序与验收

1. 先做能力证据和职业记忆共用的「列表 → 详情 → 编辑」。用长标题、不同确认状态和过期记忆核对窄屏浏览、返回位置、按记录恢复草稿及版本冲突处理。
2. 再做「我的技能」和岗位对照。验证岗位选择与手动录入、改动条件的提示、证据引用和返回原对照。
3. 串起一次完整流程。用[演示数据](../../README.md#ui-演示数据)对照 Python、Kubernetes、RAG、地图可视化。Python 有已确认的作品或面试材料，Kubernetes 只有已确认的自述，RAG 暂无材料，地图可视化关联待复核的「周末步道路况图」。确认这份材料后返回原对照，地图可视化应更新到有作品材料。
4. 分别验证本地匹配、记忆是否可用、AI 选材预览和版本冲突，依照[职业数据边界](../ARCHITECTURE.md)核对状态。真实模型验证沿用项目授权规则。

# TRACEFOLIO 前端开发 Agent 手册

用于执行和评审 Web 重构任务。当前重构工作分支为 `ui-redesign`。根目录 [AGENTS.md](../../AGENTS.md) 中的项目约束适用于每次改动。

## 开工前

1. 查看当前分支、工作区和已暂存文件，识别现有改动。重构完成后，从 fork 的 `ui-redesign` 向原仓库 `main` 提 PR。
2. 读 [视觉与文案规范](VISUAL_GUIDELINES.md) 和 [前端构建规范](FRONTEND_STANDARDS.md) 中与任务有关的部分。涉及架构时读 [README](../../README.md)、[架构设计](../ARCHITECTURE.md) 和 [上游来源与许可](../UPSTREAM.md)。
3. 找到用户进入该流程的页面、已有组件和数据来源。核对当前正常路径、空状态、保存与错误反馈，确定本次改动需要保留的行为。已有业务设计文档用于核对流程，本目录用于统一 Web 视觉与实现约定。

## 重构顺序

| 阶段 | 先做什么 | 达到什么结果再推广 |
| --- | --- | --- |
| 基础规范 | 将颜色、字体、圆角和间距接入全局样式。统一高频的按钮、输入框、状态标签、弹窗和页面容器。 | 通用状态、焦点和布局从共用组件取得。 |
| 能力证据 | 在 `/intelligence` 走完添加材料、查看来源、编辑、本人确认、AI 使用许可和版本冲突。 | 用一个完整用户流程验证组件组合、文案和数据边界。 |
| 投递 | 在 `/pipeline` 验证宽表格、长标题、阶段信息、窄屏重排和操作。 | 表格和操作在桌面、窄屏都可读可用，横向滚动留在表格区域。 |
| 其余 Web 页面 | 推广至职业智能其他区域、控制中心、校招信息库、简历工作台、JD 匹配、面试、求职资料库、设置和全局 Agent。 | 按真实入口验收，保持共用组件一致。岗位和资料详情核对直达与返回。 |
| 简历编辑与预览 | 单独核对编辑器工具区与纸张预览的边界。 | 检查保存、分页、缩放和导出。用同一份虚构简历对照页面预览和导出结果。 |

## 实现时

- 从现有共享组件组合页面。需要新变体时，先确认用途和复用范围，再决定放在基础组件还是业务组件。按项目要求保留上游许可和已导入源码的修改说明。
- 依据现有 API、状态和版本字段渲染业务结果。涉及确认、AI 许可、有效期、资料引用或保存冲突时，对照同一流程的服务逻辑及相关测试，再修改展示或交互。
- 用来源、确认状态和使用许可说明职业资料。AI 建议清晰标识，写入沿用用户确认流程。模型相关验证使用假运行时，真实模型调用遵循根目录的项目规则。
- 将本次引入的例外限定在具体场景，并记录原因与影响。跨页面改动同步更新对应文档与共用实现。

## 验收与交接

- [ ] 从正常入口实际走通改动的流程。查看桌面和窄屏，跨断点的布局再看中等屏。
- [ ] 用键盘操作关键控件，检查焦点、弹窗关闭后的返回、可访问名称和需要强化的对比度。
- [ ] 按适用状态核对空白、加载、提交中、成功、失败与版本冲突。涉及职业数据时核对来源、确认、过期和 AI 许可。
- [ ] 检查中英文界面、长文本和数字。涉及简历预览时检查对应的导出结果。
- [ ] 应用代码改动用 Node.js 22+，运行相关测试、`npm run lint`、`npm run typecheck` 和 `npm run build`。覆盖共享组件或多个工作流时运行 `npm test`。仅改文档时检查链接、命令、路径和 `git diff --check`。
- [ ] 汇报改动范围、实际通过的验证和无法验证的场景。共享样式或布局变动时，优先用桌面和窄屏截图说明变化。提交前查看差异，保持其他人的在途改动独立。

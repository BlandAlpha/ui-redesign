# TRACEFOLIO Web 前端构建规范

本规范适用于 `ui-redesign` 的 Web 工作台及公共组件。先查 [视觉与文案规范](VISUAL_GUIDELINES.md) 中的颜色、字级和用词，再按下面的规则落实组件和页面。迁移顺序与验收见 [开发 Agent 手册](AGENT_PLAYBOOK.md)。

## 组件与样式的归属

| 改动 | 首选位置 | 做法 |
| --- | --- | --- |
| 颜色、字体、圆角等共用样式变量 | [`src/app/globals.css`](../../src/app/globals.css) | 在全局定义语义用途，让组件引用变量。页面通过语义样式取色。 |
| 按钮、表单控件、弹窗、菜单 | [`src/components/ui`](../../src/components/ui/) | 复用或调整现有 shadcn/Base UI 组件。通用差异用现有变体能力表达。 |
| 页面外壳、导航、页标题 | [`src/components/app`](../../src/components/app/) | 共用主区域对齐线、标题结构和导航状态。调整导航时核对链接、直达和返回行为。 |
| 业务内组件 | [`src/components`](../../src/components/) 下的业务目录 | 将表单字段、状态映射和操作留在对应业务。多个页面确有同一模式时，再提取共用结构。 |
| 界面文字 | [`messages/zh-CN.json`](../../messages/zh-CN.json) 与 [`messages/en.json`](../../messages/en.json) | 新增或改动可见文案与可访问名称时，沿用 `next-intl` 和现有命名空间，更新两份语言文件。 |

项目沿用 [`components.json`](../../components.json) 中的 shadcn 配置，交互基础使用 Base UI。组件源码随项目维护，按需评估并合并上游改动。新增通用控件前先查同类组件和变体。功能图标从 `lucide-react` 按名称导入，同一操作对照已有页面选取图标。 [shadcn](https://ui.shadcn.com/docs) · [Base UI 弹窗](https://base-ui.com/react/components/dialog) · [Lucide React](https://lucide.dev/guide/react)

## 页面网格

网格从主内容区开始。桌面侧栏独立于内容网格。页标题、工具栏和正文共用左、右对齐线，页面主体按内容决定跨列。

| 视口宽度 | 主内容网格 | 左右页面边距 | 列间距 |
| --- | ---: | ---: | ---: |
| `<640 px` | 4 列 | 16 px | 16 px |
| `640–1023 px` | 8 列 | 24 px | 24 px |
| `≥1024 px` | 12 列 | 32 px | 24 px |

- 使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 px` 间距。组件内部优先用自然宽度、Flex 或局部网格处理；表单分组、横向工具栏和表格列按内容安排。
- 普通工作区内容上限 `1280 px`，表单和长文约 `720 px`。投递表格和简历编辑器用宽布局，列或纸张预览根据工作内容取宽。
- 手机上先排标题、关键状态和主要动作。分栏内容按阅读顺序堆叠。宽表格在自己的可滚动区域处理溢出，页面本身保持在视口内。简历预览沿用自己的分页、缩放和导出布局。

## 页面层级和分隔

| 位置 | 间距 | 实现 |
| --- | ---: | --- |
| 页标题到工具栏、标签导航或首块内容，相邻主要区块 | 24 px | `WorkspaceHeading` 配合 `workspace-stack`，或使用 `gap-ui-section` |
| 区块标题到正文、同组卡片、卡片正文到操作带 | 16 px | `gap-ui-block` |
| 字段标签到输入框、同组控件或相邻操作 | 8 px | `gap-ui-control` |

页标题下统一留白，依靠字号和间距标出层级。细线用于标出实际边界，如表格行、分栏、工具栏与滚动区域、卡片独立操作带。相邻区域已经有卡片轮廓时，留白即可。简历编辑器和档案详情的固定工具栏用细线标明工具栏与内容的边界。

## 圆角、边界和操作层级

浏览与比较记录时使用 [卡片设计规范和验收示例](CARDS.md)。

| 圆角 | 用途 |
| --- | --- |
| `6 px` | 小标签、紧凑选中底 |
| `8 px` | 按钮、输入框、菜单项 |
| `12 px` | 卡片、下拉面板 |
| `16 px` | 弹窗、大面板 |
| 全圆 | 头像、开关轨道 |

一组内容默认用一层可见边界。卡片里的多条记录用留白、分隔线和行内操作组织。当内部区域有自己独立的交互、滚动或背景时，可再设一层容器。弹窗等浮层用轻阴影区分层级。

工作区卡片和表单控件默认用描边，悬停与选中用颜色区分，键盘焦点保留可见焦点环。搜索框共用 `SearchInput`，高度为 `44 px`，用图标和单层描边标识。分段控件共用 `segment-group` 和 `segment-item`，每一段等宽，选中时表达状态，较长标签可以换行。单个卡片的下拉框与同行提交按钮同用 `h-ui-field` 高度。

紧贴的两层轮廓采用同心圆角。内层圆角取 `max(0, 外层圆角 − 内缩距离)`。例如预览外框 `16 px`、内缩 `4 px` 时，内部预览为 `12 px`。弹窗内独立的按钮仍用 `8 px`。

每个操作区突出一个主动作。次要动作使用描边、轻底或文本样式。删除等危险动作使用明确的动词和危险操作样式。图标、强调色和层级与动作的重要性保持一致。

## 交互、数据和可访问性

- 优先用原生语义和已有组件。表单字段有可见标签，错误信息和对应字段关联。键盘可以走完整个流程，焦点可见。检查弹窗打开时的焦点、关闭后的焦点返回以及菜单和链接的键盘操作。
- 布局和组件按适用状态检查空白、加载中、等待提交、成功、失败及冲突。执行结果以实际响应为准。版本冲突提示查看最新记录，保留现有的版本检查和处理路径。
- 能力证据与职业记忆的材料来源、本人确认、有效期、AI 使用许可和 AI 建议各有独立的语义。新 UI 读取现有字段并复用现有保存和权限流程。演示或验证时使用虚构材料。 [项目数据边界](../ARCHITECTURE.md)
- 界面文案跟随应用语言。变量、计数和日期沿用本地化格式。查看真实可能出现的长岗位名、错误提示和中英文混排，确认布局能换行或提供查看全文的方式。
- 颜色、焦点和触控目标按 [视觉与文案规范](VISUAL_GUIDELINES.md) 核对。在缺少模型配置的情况下检查相关引导和基础流程。

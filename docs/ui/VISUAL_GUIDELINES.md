# TRACEFOLIO Web 视觉与文案规范

2026-11-20 · `ui-redesign` 设计基线

TRACEFOLIO 是用户用来整理真实经历、回看材料并准备下一步的个人职业档案。打开页面应先看见自己的内容、当前状态和可执行的动作。暖色背景、自然的中文排版和直接的措辞提供亲切感。清楚的材料来源与操作结果体现「有据可循」。

组件、布局和交付要求见 [前端构建规范](FRONTEND_STANDARDS.md)。

## 品牌标志与浅色主题

当前使用 [TRACEFOLIO 标志](../../public/brand/tracefolio-mark.svg) 原版。标志重绘和换色由用户后续决定。本轮将苔绿和暖纸白应用于界面。品牌名写作 `TRACEFOLIO`，品牌短句可用「有据可循的职业成长」。左上角以标志和品牌名组成识别区。

| 颜色角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 苔绿 | `#315D4C` | 主按钮、链接、键盘焦点 |
| 深苔绿 | `#264C3D` | 主按钮悬停和按下 |
| 浅苔绿 | `#E5EDE5` | 选中导航和低强调选中底，搭配苔绿文字 |
| 暖纸白 | `#F7F5EF` | 页面背景 |
| 浅米白 | `#FFFDF8` | 表单、详情和弹窗表面 |
| 墨黑 | `#262A25` | 标题、正文和主要数据 |
| 灰绿 | `#5F655C` | 来源、时间和补充说明 |
| 暖灰 | `#DFDCCF` | 分隔线和装饰性容器边框 |
| 深暖灰 | `#817E70` | 需要靠边界识别的输入框或控件 |
| 陶土棕与浅陶土 | `#93442F` / `#F2E4DC` | 少量品牌细节或材料类别标签 |

状态通过文字表达，图标和底色辅助扫读。以下前景与背景配对用于浅色界面。

| 状态 | 前景 / 背景 | 标签示例 |
| --- | --- | --- |
| 成功、已完成、已确认 | `#2F654F` / `#E5EFE8` | 已保存、本人已确认 |
| 待处理 | `#7B4E12` / `#FFF1D9` | 待确认 |
| 错误、危险操作 | `#A02F35` / `#FAE8E7` | 保存失败、删除记录 |
| AI 建议 | `#594677` / `#EEE8F5` | AI 建议 |

普通文本最低对比度 `4.5:1`。识别控件或状态所需的边界和图形最低 `3:1`。参考组合中，主按钮白字约 `7.50:1`，灰绿文字在暖纸白上约 `5.50:1`。悬停、选中和聚焦时按实际背景复核。深色主题若后续启用，沿用颜色角色并单独校验色值。 [WCAG 2.2 对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) · [非文本对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)

## 字体与字级

日常界面用无衬线。英文与数字用 Inter。简体中文优先使用苹方、微软雅黑，末级使用可用的 Noto Sans CJK SC 或系统字体。考虑本地运行时，字体缺失时走本机回退。品牌短句可用 Noto Serif SC，回退到系统宋体。工作台标题、岗位名、表单、表格和编辑界面使用无衬线。 [Inter](https://rsms.me/inter/) · [Noto CJK](https://github.com/notofonts/noto-cjk)

| 层级 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页标题，桌面 | `32 / 44 px` | 600 |
| 页标题，移动端 | `26 / 36 px` | 600 |
| 区块标题 | `22 / 32 px` | 600 |
| 条目标题 | `16 / 24 px` | 600 |
| 正文 | `15 / 24 px` | 400 |
| 表单输入 | `16 / 24 px` | 400 |
| 时间、来源和次要信息 | `13 / 20 px` | 400 |

标签用 500，层级通过字重、尺寸和留白表达。表格中需要纵向对齐的数字使用等宽数字。简历页面内的编辑控件遵循此规范，简历纸张上的字体、排版和导出版式遵循用户选用的简历模板。

## 图标、图形与动效

- 功能图标用 Lucide 线性风格。行内 `16 px`，导航 `20 px`。同一动作跨页面使用同一图标。关键动作带可见文字，纯图标按钮带可访问名称。 [Lucide React](https://lucide.dev/guide/react)
- 品牌或首次使用场景可以用项目材料、笔记或路径相关的图形。工作页面优先用内容和留白组织信息。图表标明数量、单位和来源，如「3 条岗位要求有材料支持」。
- 悬停、选中和面板展开的过渡以 `120–180 ms` 为默认。考虑 `prefers-reduced-motion`。键盘焦点清晰可见，常用触控动作以 `44 × 44 px` 的有效点击区域为设计目标。

## 文案与人称

逐项检查界面文字是否帮助识别对象、操作、状态、后果或下一步。把重复标题、口号、重复计数和装饰性说明删掉。排版和通用图标足以说明用途时，保留可访问名称即可。授权、错误、数据来源、破坏性操作后果和输入要求在实际操作处写清楚。

按钮和标题通常省略人称，动词在前，对象明确。需要和用户说话时用「你」。系统反馈直接描述结果。「我」用于用户自己的声明，或明确标识为 Agent 的对话。AI 生成内容在结果附近标为「AI 建议」。

| 场景 | 写法 |
| --- | --- |
| 按钮 | 添加证据、查看来源、保存简历版本 |
| 初次使用 | 你可以从一份项目材料开始。 |
| 空列表 | 添加一份项目材料，记录你做了什么。按钮用「添加证据」。 |
| 用户声明 | 我已核对这条记录。 |
| 系统反馈 | 已保存到本机。仅在实际保存成功后显示。 |
| 版本冲突 | 这条记录已在另一窗口更新。请查看最新版本后再编辑。 |
| Agent 对话 | 我建议补充你在项目中的具体贡献。 |

一条记录上分别写清材料来源、谁确认过、是否允许用于 AI。常用标签为「项目材料」「面试记录」「自述」「待确认」「本人已确认」「允许用于 AI」。本人确认表示用户核对过材料。授权文字说明哪些材料在什么操作中可能发给哪个服务。失败说明发生了什么和下一步可执行的动作。涉及承诺时，以实际保存状态、权限和产品能力为准。 [职业数据与事实边界](../ARCHITECTURE.md)

同一概念使用固定术语。中英文对齐动作对象、状态和权限含义。英文界面用句式大小写，中文用全角标点。按钮使用短语，帮助和错误提示使用完整句子。

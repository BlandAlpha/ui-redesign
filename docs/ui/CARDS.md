# Web 卡片设计规范

卡片用来浏览、比较或打开一条记录。先确定用户必须看见的内容，再选卡片形式。只有一个操作入口的简单内容优先用带图标的列表行，表单分组优先用标题和间距。

## 信息按固定位置排列

| 位置 | 内容 | 排版 |
| --- | --- | --- |
| 顶部 | 类型或上下文，右侧放辅助操作 | 左侧一行，右侧操作同高、同距。状态和动作与标题分开。 |
| 标题 | 记录名称，如岗位或简历名 | `16 / 24 px`，600 字重。同行卡片都为标题留两行，完整名称可通过打开记录查看。 |
| 摘要 | 对选择有用的描述、关联项或材料数量 | `13 / 20 px`，最多两行。没有内容时留白。 |
| 底部 | 日期、模板或状态 | 置于同一条底线。日期使用当前界面语言的格式。空间不足时收起次要标签或调整所在列数。 |

记录卡片统一使用 `12 px` 圆角、`16 px` 内边距和一条暖灰边框。焦点环不参与布局，悬停以颜色变化表示。能区分记录的实际预览可放在固定尺寸的媒体区域。通用文件夹图标只占一行内的小图标位置。

## 同组对齐

同一网格里的卡片使用同一组件和相同的版式轨道。标题、摘要、底部和操作区分别对齐。两行标题、无摘要、无状态或只有一个操作时也应对齐。文字允许在固定行数内换行，长英文和连续字符使用断词。小屏通过减少列数保持信息清晰。

指标卡使用「名称 → 数值」两个位置，同组名称、数值和图标对齐。选项卡使用「名称和必要说明 → 控件」，控件位置固定。工作区面板随内容自然生长。只有同组需要比较的记录、指标或选项使用统一轨道。

## 操作和验收

- 记录标题是打开详情的可聚焦入口，卡片可以扩大这一入口的点击区。复制、重命名、删除使用独立控件和可访问名称。用键盘打开卡片时，按顺序可到达每个辅助操作。
- 在同一组放入短标题、两行标题、无摘要、长英文和缺少状态的数据。浏览器中测量各卡片顶部到标题、摘要、底部和操作区的距离，同一网格下这些距离应一致。
- 在桌面并排验收，在 `320 px` 宽的浏览器中检查内容收敛为一列。检查放大文字后的可读性和完整名称的访问路径。

## 可直接检查的实践案例

简历和资料库共用 [RecordCard](../../src/components/ui/record-card.tsx)。新卡片把业务字段传入对应位置，例如标题传简历名，上下文传「原简历」，摘要传岗位或简历说明，底部传模板与编辑日期。记录名称和辅助操作各自绑定对应动作。标题和摘要由组件分配行高，业务页面决定网格列数。

| 页面 | 样例 | 检查点 |
| --- | --- | --- |
| `/resume` | 一份原简历和一份岗位定制简历 | 较长的名称或两行摘要时，「学术」与编辑日期仍在同一条底线上。网格和列表沿用同一卡片的阅读顺序。 |
| `/library` | 按岗位查看包含不同类型成果的档案，切换为按分类 | 岗位名称优先显示。公司、地点或类别提供上下文。成果和更新时间各在固定位置。 |
| `/match`、`/interview` | 选择简历来源及后续选项 | 来源选择有清楚的选中状态。独立设置使用共享开关，单选模式使用单选控件。 |

# TRACEFOLIO Web UI

为用户整理真实经历和准备求职下一步。页面优先让用户看到自己的内容、当前状态和一个可执行的主动作。亲切感来自暖纸色、自然排版和直接措辞。「有据可循」体现在明确的材料来源、确认状态和操作结果。

## 使用范围

- 从实际入口确认任务范围，查看工作分支和在途改动。当前重构使用 `ui-redesign`。按根目录 [AGENTS.md](../../../AGENTS.md) 执行项目约束。分析或仅记录的任务产出结论与文档；实施任务按用户确认的范围执行。
- [前端开发手册](../../../docs/ui/AGENT_PLAYBOOK.md) 提供迁移顺序与交接清单。把 [UX 清单](../../../docs/ui/UX_BACKLOG.md) 和 [职业智能交互重设计记录](../../../docs/ui/CAREER_INTERACTION_PROPOSAL.md) 用作走查依据。交互重设计记录是待实施提案，进入相应专题时先确认本次范围。

## 视觉和页面层级

- 品牌写作 `TRACEFOLIO`，使用 [现有标志](../../../public/brand/tracefolio-mark.svg)。界面以苔绿 `#315D4C` 提示主动作与焦点，浅苔绿 `#E5EDE5` 表达选中，暖纸白 `#F7F5EF` 作页面底色，浅米白 `#FFFDF8` 作工作表面，墨黑 `#262A25` 作主文字。用 [全局样式](../../../src/app/globals.css) 的语义变量取色。状态靠文字表意，颜色和图标辅助。状态色、对比度与动效细则见 [视觉与文案规范](../../../docs/ui/VISUAL_GUIDELINES.md)。
- 界面使用无衬线，英文和数字用 Inter，中文回退到苹方、微软雅黑、Noto Sans CJK SC 与系统字体。按字号/行高使用桌面页标题 `32/44`、移动端 `26/36`、区块标题 `22/32`、条目标题与输入 `16/24`、正文 `15/24`、次要信息 `13/20 px`。标题 600、标签 500。简历纸张及导出遵循用户选中的简历模板。
- 页头、工具栏和正文共用内容对齐线。从主内容区起排 `4 / 8 / 12` 列，在 `640 / 1024 px` 切换，左右边距为 `16 / 24 / 32 px`，列间距为 `16 / 24 / 24 px`。普通工作区上限 `1280 px`，长文和表单约 `720 px`。宽表格在内部滚动，窄屏按阅读顺序堆叠。例外场景和实现位置见 [前端构建规范](../../../docs/ui/FRONTEND_STANDARDS.md)。
- 标题到首块内容、相邻主要区块用 `24 px`，区块标题到正文、同组卡片和卡片操作带用 `16 px`，同一字段的标签与控件、相邻操作用 `8 px`。复用 `WorkspaceHeading`、`workspace-stack`、`gap-ui-section`、`gap-ui-block` 和 `gap-ui-control`。标题下统一留白。细线标示表格行、分栏、固定工具栏或独立操作带的实际边界。
- 首页按重要程度分配空间。最大的区块只呈现当前下一步，次级区块展示近期证据，统计和可选功能放在普通层级或相应页签。用空档案、待复核和已有成长任务三个状态检查首页动作。现有案例见 [CareerOverview](../../../src/components/career/career-workspace.tsx)。

## 组件和卡片

- 复用仓库维护的 shadcn/Base UI 组件。共享的视觉、状态和键盘行为留在 `src/components/ui`，业务字段和流程留在各工作区。图标用 Lucide 线性风格，行内常用 `16 px`、导航 `20 px`。相同动作使用相同图标，纯图标按钮有可访问名称。
- 工作区采用扁平描边，常驻卡片和输入框靠边线与色彩区分层次，浮层可以用轻阴影。圆角按用途选 `6 px` 小标签、`8 px` 按钮和输入、`12 px` 卡片及下拉面板、`16 px` 弹窗。贴合嵌套轮廓按「外圆角减内缩距离」算内圆角，最小为零。独立控件保留自身圆角。
- 搜索复用 `SearchInput`，高度 `44 px`。简历来源等分段控件复用 `segment-group` / `segment-item`，各段同宽，检查较长英文、选中态和键盘焦点。独立布尔设置使用 [Switch](../../../src/components/ui/switch.tsx)，轨道与圆点垂直居中，两端留距一致。多选一使用单选或相应标签页。
- 同组记录复用 [RecordCard](../../../src/components/ui/record-card.tsx)。固定类型、标题、摘要、底部元信息和辅助操作的位置。用单行标题、两行标题和无摘要并排检查，日期和标签共用底线。岗位、地点和有实际区别的成果优先展示，通用文件夹图标只占行内位置。卡片可聚焦打开，编辑、复制或删除各自独立。
- 表单卡片按内容生长。以 [成长计划卡片](../../../src/components/career/growth-plan-card.tsx) 为例，状态文字对齐标题首行，桌面下拉框与按钮同高 `44 px`、间距 `8 px`，窄屏上下排列。[卡片规范](../../../docs/ui/CARDS.md) 有简历、资料库、选择来源和成长计划的浏览器验收案例。

## 文案和业务状态

- 每段文字应帮助识别对象、操作、状态、后果或下一步。删掉口号、重复标题和重复解释。常见图标能承担信息时保留可访问名称。输入要求、授权、错误和删除后果在操作发生处写清楚。
- 按钮用简短的动词加对象，例如「添加证据」。需要称呼用户时用「你」，用户声明用「我」，Agent 的第一人称明确标识说话方。反馈说明实际结果，例如「已保存到本机」。固定术语，在 `messages/zh-CN.json` 和 `messages/en.json` 同步可见文字和可访问名称。
- 界面分别表达来源、本人确认、有效期和 AI 许可，并清楚标出 AI 建议。本人确认表示用户已核对材料。按实际的数据、状态和许可展示反馈，沿用版本检查与证据更新引起的关联任务失效。涉及这些流程时查阅 [项目架构和职业数据规则](../../../docs/ARCHITECTURE.md)。

## 验收

- 用 [本地 UI 演示数据](../../../README.md#ui-演示数据) 从真实页面入口走通流程。检查桌面与 `320–390 px` 窄屏，涉及网格时覆盖断点。用长标题、中英文和空字段检查同组卡片对齐。确认搜索无阴影、分段等宽、焦点可见，交互完成后可以返回原入口。
- 按任务覆盖空白、加载、提交、成功、失败和版本冲突。涉及职业记录时使用虚构数据核对确认、过期、许可和引用。应用改动按项目要求运行测试、Lint、类型检查和构建。仅改文档时核对链接、命令与差异。
